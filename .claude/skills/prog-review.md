# Skill: 代码审查 (prog-review)

## 触发场景
用户提交了一段 Ren'Py/Python 代码，需要审查。

## 审查清单

### 架构合规
- [ ] 变量是否在 `datastore.rpy` 中用 `default` 声明
- [ ] 状态修改是否通过 `api.rpy` 中的函数
- [ ] 是否有多余的 `default` 散落在其他文件

### 代码质量
- [ ] 是否有未使用的变量/函数/import
- [ ] 是否有静默的异常吞没（bare except / pass on error）
- [ ] 是否有不必要的防御性检查
- [ ] 是否有死代码或注释掉的代码

### Ren'Py 特有
- [ ] `call` vs `jump` 使用正确
- [ ] Screen Language 语法正确
- [ ] 字符串中 `[]` 是否被正确转义
- [ ] 是否正确区分了 `default` 和 `define`

### 注释
- [ ] 新增函数是否有中文文档注释
- [ ] 复杂逻辑是否有 "为什么" 注释
- [ ] 是否有废话注释（`# 循环` `# 返回` 等）

## 输出格式
```
## 审查结论
[PASS / NEEDS FIX]

### 必须修改（阻断性问题）
- 文件:行号 — 问题描述 → 建议修改

### 建议修改（非阻断）
- 文件:行号 — 问题描述 → 建议修改

### 通过项
- 列举通过检查的项目
```
